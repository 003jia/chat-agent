# 接口测试编写规范

> 适用于 `{{TEST_DIR_SINGLE}}`、`{{TEST_DIR_FLOW}}`。本文件是用例编写的质量门禁，具体响应路径必须以 `{{DOC_DIR}}` 文档和源码为准。
>
> 示例以 pytest/Python 表达；其他语言和框架保留相同的覆盖、断言、清理和诊断要求，并替换为项目对应语法。

## 1. 数据获取

- 禁止依赖固定 ID、固定邮箱、固定列表顺序或“环境当前为空”的假设。
- 优先通过查询接口动态获取目标数据；数量不足时使用明确原因 `skip`，不要伪造不满足前置的数据。
- 需要破坏性操作时，先创建带唯一前缀的临时数据，再只删除自己创建的数据。
- 随机值使用 `{{UNIQUE_DATA_METHOD}}`，不要使用可能冲突的固定名称。

```python
items = api.list_items(page=0, page_size=100)
content = extract_items(items)  # 按项目响应格式实现
if len(content) < 2:
    pytest.skip("需要至少 2 条可操作数据")
```

## 2. 响应访问与断言

统一先验证请求结果，再取业务字段：

```python
assert response["status_code"] == {{SUCCESS_HTTP_STATUS}}, (
    f"请求失败: status={response.get('status_code')}, "
    f"error={response.get('error')}, data={response.get('data')}"
)
data = response.get("data")
assert data is not None, "成功响应不应为空"
```

- 根据项目响应包装明确取值路径，例如 `data.items`、`data.data.content` 或 `body.result`。
- 不要用宽泛的 `or {}`/`or []` 掩盖成功响应为空或结构异常；防御性访问之后仍要对必需字段做强断言。
- 每个关键断言带清晰错误信息，说明接口、字段、期望和实际值。
- 写操作不能只断言“返回成功”：创建后查询存在，更新后查询字段，删除后查询不存在，状态变更后查询状态。
- HTTP 状态码和业务码分别断言，不能用一个断言替代另一个。

## 3. 用例覆盖

每个接口至少分析以下场景，按业务适用性落地：

- 正常请求和最小有效请求。
- 必填字段缺失、空值、类型错误、非法枚举、边界值和超长值。
- 未认证、无权限、不同角色和跨租户/跨资源访问。
- 资源不存在、重复创建、重复提交、幂等和并发语义。
- 分页第一页/最后一页/空结果/非法分页参数。
- 批量接口的空列表、单项、多项、部分失败和结果闭环。
- 文件上传的格式、大小、空文件和重复上传。
- 异步接口的完成、失败、超时和重复轮询。

如果某场景不适用，在测试文档中写出排除理由，而不是静默遗漏。

## 4. 单接口与业务流程

单接口用例放在 `{{TEST_DIR_SINGLE}}`：

- 一个接口一个测试类或等价的清晰分组。
- 通过参数化覆盖同一规则的边界值。
- 角色权限用例打上 `{{PERMISSION_MARK}}`，覆盖“有权限成功、无权限被拒绝”。

业务流程用例放在 `{{TEST_DIR_FLOW}}`：

- 一个业务场景一个测试方法。
- 用 `# Step N:` 记录前置、核心操作、结果验证和清理。
- 流程中每一步都验证关键中间结果，避免只验证最终 HTTP 200。
- 创建数据的流程必须有完整的 `finally`/`afterEach` 清理。

## 5. 账号保护与数据清理

- 权限测试使用 `{{PRESET_ACCOUNTS}}`；禁止修改预置账号角色、部门、授权和资源归属。
- 需要被操作对象时使用专门目标账号或临时创建账号。
- 修改已有数据前保存原始状态，结束后恢复；批量修改要逐个保存和恢复。
- 临时数据必须登记 cleanup 状态，即使创建到一半或断言失败也能清理。
- 父子资源按依赖逆序删除：先子资源，再父资源。
- 清理失败要记录日志并使结果可见，不能简单吞掉异常。

## 6. 日志和报告

每个业务步骤记录可定位日志：

```python
logger.info("Step 1: 获取目标资源")
logger.info("Step 2: 执行更新 resource_id=%s", resource_id)
logger.info("Step 3: 查询确认更新结果")
```

测试报告必须按 `{{REPORT_ARCHIVE_RULE}}` 归档，至少包含：

- 测试命令、环境和代码版本。
- 通过/失败/跳过数量。
- 失败用例、请求上下文、响应摘要和诊断层级。
- 需要时附原始报告、HTML、日志、trace/video 等工件。
