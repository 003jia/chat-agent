# API 特殊行为与坑点沉淀

> 这是运行中持续更新的活文档。只有有证据的特殊行为才能写入；证据来源为源码、接口文档、环境实测或缺陷单。

## 使用规则

- 先查本文件，再查最新接口文档和源码。
- 项目差异必须标注 `{{ENV_SET}}` 中的具体环境。
- 不把偶发网络故障写成接口行为。
- 每个坑点都要给出对测试断言、数据准备或清理方式的影响。

## 记录模板

```markdown
## {{序号}}. {{接口/功能名}}（{{日期}}新增）

**环境**：{{ENV}}

**现象**：{{实际请求和响应现象}}

**证据**：{{源码路径/文档章节/实测日期/缺陷单}}

**原因**：{{源码或环境层面的原因；不确定时写“待确认”}}

**测试影响**：
- 请求参数：{{影响}}
- 响应取值/断言：{{影响}}
- 前置数据/权限：{{影响}}
- 清理/重试：{{影响}}

**测试写法**：{{应该如何编写或修复用例}}

**关联用例/文档**：{{TC-ID、测试文件、接口文档}}
```

## 重点关注清单

- HTTP 状态码与 body 业务码含义不一致。
- 前端类型、接口文档与后端真实返回不一致。
- 响应在不同参数/环境下结构不同。
- 枚举大小写、空字符串、`null`、默认值语义特殊。
- 分页、排序、过滤字段名与字面含义不一致。
- 写操作返回成功但持久化延迟或需要查询闭环。
- 批量操作部分成功、非原子或重复提交行为特殊。
- 权限计算、越权绕过、跨租户访问风险。
- 异步任务状态、冷却期、轮询和最终一致性。
- 上传/导出文件格式、大小、临时资源和清理要求。
