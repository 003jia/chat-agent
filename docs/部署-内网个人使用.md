# 内网个人部署指南

本文档说明如何把 Memory Agent Workbench 部署到一台内网服务器（或 NAS / 家用主机），供个人或小团队在局域网内使用。

部署后访问方式：浏览器打开 `http://<服务器IP>:8787`，前后端由同一个 Node 进程提供，无需额外配置 CORS。

## 前置条件

- 一台可长期运行的机器（Linux 建议，macOS/Windows 亦可），Node.js ≥ 22
- 方式 A（直接跑）：Node.js + npm
- 方式 B（推荐，容器化）：Docker + Docker Compose
- 至少一个模型的 API Key

## 配置环境变量

复制 `.env.example` 为 `.env` 并填写：

```bash
cp .env.example .env
```

必填项：

| 变量 | 说明 |
|---|---|
| `HOST` | 监听地址，内网部署填 `0.0.0.0` |
| `PORT` | 端口，默认 `8787` |
| `MEMORY_AGENT_ADMIN_TOKEN` | 管理令牌（必填），浏览器首次进入需要输入 |
| `MEMORY_AGENT_API_KEY_*` | 至少配一个模型的 API Key |

## 方式 A：直接运行

```bash
npm install
npm run build          # 构建前端到 dist/
source .env            # 加载环境变量
npm start              # node server/index.mjs
```

验证：

```bash
curl http://127.0.0.1:8787/api/health
```

浏览器打开 `http://<服务器IP>:8787`，输入 `.env` 里设置的 `MEMORY_AGENT_ADMIN_TOKEN`。

> 建议用 systemd / pm2 守护进程，实现开机自启与崩溃重启。

## 方式 B：Docker Compose（推荐）

```bash
# 编辑 .env（至少设置 MEMORY_AGENT_ADMIN_TOKEN）
cp .env.example .env

# 构建并启动
docker compose up -d --build

# 查看日志
docker compose logs -f
```

- 数据保存在宿主机 `./data/` 目录（已通过卷挂载持久化），容器重建不丢失。
- 更新代码后重新执行 `docker compose up -d --build` 即可。

## 数据与备份

所有数据都在 `data/` 目录下：

```text
data/config/            # 角色、模型配置（含 API Key）
data/conversations/     # 会话记录
data/tasks/             # 工具任务
data/memory/            # 长期记忆（index.json / memory.md / raw 审计日志）
data/backgrounds/       # 角色自定义背景
```

**请定期备份整个 `data/` 目录**，例如：

```bash
tar czf memory-agent-backup-$(date +%F).tar.gz data/
```

建议每天定时备份（cron 或 NAS 快照）。

## 安全注意事项

- 内网部署不等于完全安全：`MEMORY_AGENT_ADMIN_TOKEN` 请使用足够长的随机字符串（`openssl rand -hex 32` 生成）。
- `data/` 内含 API Key 和私人会话/记忆，不要放进公开仓库，也不要通过 HTTP 暴露在公网。
- 若需要公网访问，请先加反向代理 + HTTPS（如 Caddy / nginx），不要在裸 HTTP 下暴露。
- 更换令牌后，旧浏览器会话需要清除本地 sessionStorage 重新输入。

## 常见问题

**浏览器打开页面但接口报 CORS 403**
同源托管下不应出现。如果出现，说明浏览器访问的地址与令牌来源不一致，清掉 sessionStorage 重试。

**`docker compose up` 报 MEMORY_AGENT_ADMIN_TOKEN 未设置**
在 `.env` 中填写该变量后重试。

**改了前端代码没生效**
`npm run build` 重新构建（方式 A），或 `docker compose up -d --build`（方式 B）。

**忘记管理令牌**
直接改 `.env` 中 `MEMORY_AGENT_ADMIN_TOKEN` 并重启服务；浏览器端清除 sessionStorage 后重新输入。
