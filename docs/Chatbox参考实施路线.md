# Chatbox 类型产品参考与实施路线

## 参考边界

当前项目参考 Chatbox 的产品类型和高频工作流，不复制其源码、品牌或界面。Chatbox Community Edition 使用 GPLv3，本项目保持独立实现。

参考来源：

- https://chatboxai.app/zh
- https://chatboxai.app/zh-TW/guide/getting-started/interface-overview
- https://chatboxai.app/zh/help-center/chatbox-ai-service-faqs
- https://github.com/chatboxai/chatbox

## 产品定位

产品形态采用“本地优先 AI 工作台”：

1. 会话是主要入口，支持多模型、流式回复、Markdown 和历史管理。
2. 角色预设对应 Chatbox 的“我的搭档”，但继续支持本项目的长期记忆和专家团配置。
3. 联网搜索、知识库和 MCP 都统一进入工具注册表，按权限执行并保留任务记录。
4. 本地数据可以搜索、导出和备份，API Key 与个人数据不得进入 GitHub。
5. 对话只是入口，长期方向仍是模型规划任务、调用工具、验证结果和交付产物。

## 分阶段实施

### 第一阶段：会话生产力骨架

- 桌面常驻、可折叠会话侧栏。
- 会话标题筛选和全局消息搜索。
- 会话置顶、重命名、删除和 Markdown/TXT/JSON 导出。
- 输入区快速切换模型供应商。
- 显示当前会话的上下文 Token 估算和 contextLength 占用。

### 第二阶段：文件理解和知识库

- 建立 `Attachment` 和 `KnowledgeBase` 数据结构。
- 文件上传先落本地，限制大小、类型和文件名。
- 文本类文件本地解析；PDF/Office 使用可替换解析器。
- 文档分块和索引与 `memory.md` 分离，回答必须保留文档引用。
- 上传内容属于不可信数据，不得作为系统指令执行。

### 第三阶段：MCP 与任务 Agent

- MCP Server 配置、启停、连接测试和工具发现。
- MCP 工具转换为现有 `AgentTool` 注册格式。
- read 工具允许自动执行；write/external 工具进入人工审批。
- 模型自动选择工具并运行有界多步骤循环。
- 每一步保存输入、输出、耗时、错误和产物引用。

### 第四阶段：产物和高级能力

- 代码、HTML、图表和文档产物预览。
- 图片生成独立工具页。
- 全量备份、恢复和版本迁移。
- 桌面封装和跨平台文件系统能力。

## 架构约束

- 长期记忆、知识库、会话历史和工具结果分层存储，禁止混成一个无限增长的 prompt。
- contextLength 必须参与预算；超过阈值时优先压缩旧会话，不全量加载。
- 工具输出默认只进入当前任务证据，稳定结论经过规则或审核后才能沉淀为长期记忆。
- 所有外部副作用必须可确认、可追踪、可失败恢复。
- 数据目录和 API Key 保持 Git 忽略，导出文件由用户主动触发。
