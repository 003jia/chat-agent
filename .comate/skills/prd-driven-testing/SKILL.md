# PRD 驱动需求测试 Skill

UI 层**需求轨** skill：承接新增/变更需求的首轮功能验收，产出后稳定的用例移交 `console-e2e-test` 回归轨。通用编调试规约继承 `console-e2e-test`；凡未在本文件重述的红线一律以其为准。

## 本 skill 配置表（本项目取值）

| 配置项 | 取值 | 说明 |
|---|---|---|
| 被测产品 | Memory Agent Workbench（聊天智能体） | 本地优先智能体工作台 |
| 需求来源 | 本仓 `docs/` 下 PRD 文档 | 如 `PRD-会话摘要-overview.md`、`PRD-会话摘要真接入AI.md`、`prd-companion-refresh.md`；路线图类见 `docs/未来目标与架构路线图.md` |
| 变动对照基线 | 当前实现 + 本仓 git 历史 | 无外部知识库镜像；用 `git log -- <路径>` 对照功能引入/演进 |
| 模块↔文档映射 | `README.md`「当前能力」节 + `docs/` 索引 | 充当模块地图，随运行完善 |
| 只读代码库 | 本仓 `src/`（前端）、`server/`（后端） | 相对测试目录只读 |
| 需求轨用例文档目录 | `docs/test-cases/requirements/` | 与回归轨 `docs/test-cases/regression/` 同层 |
| 用例归档 | 本地 TC md 即归档（无外部用例平台） | 以 TC-ID 查重 + 目录 grep 自检代替平台导入校验 |
| 运行封装单入口 | `scripts/run-and-archive.mjs` | rotate→run→generate→archive 并回传原始退出码 |
| TC 文件命名 | `TC-<模块>-00N_<英文短名>.md` | 模块取 chat/memory/tasks/settings 等小写短名 |

## 边界

- 继承 `console-e2e-test` 全部边界；只修改 `e2e/`、`docs/test-cases/` 与测试相关配置。
- 只读消费 `docs/` 下的 PRD 与路线图，不反向改写 PRD 正文（评审发现的 PRD 问题单独列出提请作者确认）。
- 仅对【尚未】被回归套件覆盖的新增/变更需求开线；存量稳定行为维护交还 console-e2e-test 回归轨。
- 不因追求覆盖率弱化任一 P0 的 core business locator 断言。
- git 历史检索只读：只用 `git log`/`git show` 做对照，不改写历史、不 revert。

## 输入模式（两种）

- **PRD 文档直链（优先）**：输入为 `docs/` 下 PRD 文件路径或功能名时，先摄取：PRD 快照（通读全文）→ 关联代码定位（前后端落点）→ 关联提交核验（`git log --grep` + `git log -- <路径>` 双路）→ 开线裁决（无合入提交且无实现时停下问用户，不自作主张）。事实包（PRD 事实源/提交清单/最新合入 commit）即九步第 1 步输入。
- **功能/模块名**：先按模块映射表定位对应 PRD 文档，进入标准九步。

## 门禁顺序（强制）

> 用例文档写完 → **用户 review 通过** → **本地基线登记** → 才允许写 POM/spec → 再跑测。
> 用例集合未经用户确认不得开写测试代码，避免评审改动后 spec 与登记双向返工。

## 标准流程（九步）

1. **定位事实源 + 变动面分析（两段产出）**：先锁定目标 PRD 文件 + 关联接口文档（`docs/api/`，缺失则先调 `api-doc-generator` 补齐）+ 前后端落点文件，并确认当前回归基线空白度。**定位完不许直接写用例**，接着产出「本次变动清单」：以本次 PRD 为主（应然），与当前实现（含 `git log` 对照的功能引入点）同模块基线逐区块 diff 打 `新增/变更/删除/未变` 四标签，用模块映射外扩波及模块与共享容器（如角色、会话侧栏、工具抽屉），代码库用于核实落地形态。清单落进 TC md，每行带出处锚点（PRD 小节 + 源文件行号）。**事实源优先级：①PRD 文档 → ②现有实现与 git 历史（变动对照与影响面）→ ③前后端代码库细节，不得倒挂。**
2. **用例转化（只到 TC-md）**：按转化 Checklist 推进——清单每一行至少一条 TC（`新增`/`变更` 给正向用例，`删除` 给「旧入口已不存在」反向断言）；写期望值前先过溯源门槛（源码只是「实然」不是「应然」；PRD + 实现交叉 + 基线 diff 核验，禁止用实现验证实现）；可行性分流贴标准延期短语与 precheck-skip 模板。**此步只产出 TC md，不写 POM/spec。**
3. **缺口过堂**：过五项固定检查位（详情页 happy-path／搜索回归靶标／多选或批量操作／locked 编辑态（如待审批任务、candidate 记忆）／空态 DOM 核验），逐一闭合或登记延期理由入册 backlog。放在评审前，避免通过后再补用例导致登记补录。
4. **用例评审门**：把 TC md 全量呈给用户 review——变动清单（逐行对应 TC）、模块划分与条数、**P 级逐档报数（P0/P1/P2/P3 各 N 条 + 延期 M 条）**、每条的步骤/预期、偏差登记表、豁免与延期项。**必须拿到用户显式确认**才进入下一步；用户提出修改则回第 2 步改稿再评审，不得边评审边写代码。评审结论记入 TC md 或提交信息。
5. **本地基线登记**：以**评审通过的 TC md 为唯一数据源**做 TC-ID 查重（`grep -rn "<TC前缀>" docs/test-cases/`）与目录落位自检，登记到 `docs/test-cases/requirements/` 索引；**没有外部用例平台，禁止为"归档"手写第二份用例内容**；登记后逐模块核对 TC-ID 集合、空值与计数。
6. **骨架落地（写测试代码）**：按产物模板写 POM class shell（extends BasePage + 私有 Locator getter + dialog 助手）与 spec（describe→登录态 fixture→beforeEach 导航→afterEach 清理残量为零）；selector 采用分级容差编码策略；数据根一律指向临时目录。
7. **三角溯源闭环**：建立 TC↔POM↔spec 三角矩阵后回头比对预期结果每条均有浏览器可视锚点；spec test 标题复制 TC-md 小标题原文以保证归档脚本 regex 命中。
8. **接入流水**：注册 package.json `"test:e2e:<module>"` 一行，必须走 `scripts/run-and-archive.mjs` 单入口封装（内部串起 rotate→run→generate→archive 并回传原始退出码）；**需求轨归档分组**：运行分组统一写 `requirements/<TC模块>/<模块槽位>`，使一个需求的全部运行记录收敛在一个文件夹下；回填依赖映射表 + 覆盖基线台账。
9. **串行试跑冻结**：首跑前过命令级陷阱与路由漂移探针（写 POM getter 前必验目标页真实可渲染；注意桌面/移动两套布局走不同 DOM）；通过后单跑一次核对归档四要素齐全。试跑若暴露实现偏差导致 TC md 修订，须按 TC-ID 回写登记索引对应用例，并同步偏差登记表。

## 用例设计原则（在 console-e2e-test 基础上追加）

- 一条需求点 = 一个 TC-ID = 一个 `test()` = 一个归档目录 = 一个业务视频。
- 步骤排列沿用用户路径：入口登录 → 页面结构 → 主流程 → 校验/筛选 → 详情/空态。
- 凡 PRD 正文出现具体卡号/条目/消息 ID 的段落一律视为**强制回归靶标**，必须有专门 TC 直接守护其描述的具体行为。
- 可行性分流贴延期签时，必须同步落到缺口过堂表的"延期理由"栏而非静默丢弃。
- **预期值不得单源于实现**：任何期望值（URL/文案/枚举项/计数/跳转目标）须过 PRD + 实现交叉；实然≠应然时按实现写断言但**必须**记入偏差登记表并上报，无依据的"仅旧版有"差异挂 pending 不写死。
- **清点类用例并列产出**：除 PRD 功能点用例外，为每个被测区块并列一条「链接清点」与一条「可点击元素行为清点」用例（双向集合比对：多出未登记即红、缺失即红）；理由——PRD 只描述主要交互，改版常顺带动到侧栏/抽屉/弹窗入口，这些回归风险不在 PRD 文字里。
- **覆盖深度必须到 P2、必要时 P3**：P2（空态/极值/长文本、次要入口、hover/tooltip/展开收起、清点类）**必须产出**；P3（动效、埋点、断网与 5xx 降级文案、多语言——本项目有 i18n 骨架）**应当产出**，判定无价值须书面理由入册。评审门按 P 级逐档报数。
- **需求变动清单是用例的上游**：每条 TC 必须能回指变动清单某一行；清单有行而无 TC 即漏测。

## 数据复原与环境保护网

- 三态（新增/修改/删除）+状态切换复原范式直接复用 `console-e2e-test` 数据复原章节；`afterEach` 末尾穷举断言残余集合为零。
- 一切数据落点在临时数据根，禁止触达真实 `data/`（用户记忆、会话、密钥）。
- 副作用前置守门：B/D 型环境依赖用 precheck-skip 范式（第二参永远带后端诊断串）；A/C 型不许仅 skip，应先修环境或加多层防御兜底。
- 外部不可逆操作（删除角色/会话/记忆、覆盖写入等）停在最终权限按钮之前，除非持有授权 + 复原方案。

## 与 console-e2e-test 的分工界面

| 场景 | 归属 |
|---|---|
| 某个 docs/ PRD 功能从未有过 automation → 首轮功能验收 | 本技能 |
| 该功能的稳定性日常巡检/失败分析/视频核对 | console-e2e-test |
| 既存用例随产品迭代微调 selector/文案 | console-e2e-test |
| PRD 变更引发的新分支用例补充评估 | 本技能评估，必要时新建 |
| 终态校验红线/等待视频纪律/归档链路操作细节 | 两轨共用，以 console-e2e-test 为准 |

需求轨用例转为长期巡检资产时：同一次改动里 `git mv` 到 `docs/test-cases/regression/` 并改「用途」列值，交回 console-e2e-test 维护。

## 完成条件

- 九步全绿且归档四要素（report/results/HTML/video+trace）当次 run 齐全；台账只记「已实跑+时间戳+skip 原因」，不把本地产物目录当证据。
- 变动清单已落表且逐行闭合：`清单行数 = 已覆盖行数 + 已登记延期行数`；每行带出处锚点（PRD 小节 + 源码位置），基线 commit 已注明。
- 覆盖深度到位：P2 条目数 > 0；P3 要么有条目要么有书面理由入册；评审记录有 P 级逐档计数。
- 缺口过堂五位要么各有兜底 TC 引用，要么书面延期理由已入册 backlog。
- 用例评审门已过：TC md 经用户显式确认后才开写代码；评审通过时间与变更点有记录。
- 本地基线登记完成且与最终 TC md 一致：TC-ID 集合、条数、模块分组三项穷举核对通过；试跑后改过的用例已按 TC-ID 回写登记。
- 已更新全局台账（回归/需求双轨 inventory + 依赖映射表 + 基线计数）。
- 元信息表「用途」列 = requirement，且文件确实位于 `docs/test-cases/requirements/` 下（grep 自检）。
